# Portable field notes

Read the comprehensive `skills/rock-build/SKILL.md` plus `mcp/reference/rock-runtime-gotchas.md`. Historical behavior must be verified on the actual version. No inherited numeric ID is configuration.

## How to read the tags

Newer entries end with a provenance tag. Pick the lowest tier the evidence supports, and promote an entry when someone re-tests it on a live installation.

- `measured`: seen on a live Rock installation. The tag names the Rock version and date when they were recorded.
- `traced`: read from Rock source code, release notes or official Spark documentation, with the source named.
- `summarized`: condensed from another builder's published write-up and not re-tested by this kit's authors.
- `verified on <Rock version>, <date>`: added when an entry is re-checked live.

"Observed on Rock 19.8.1" means one installation running that version showed the behavior on that date. It is not a claim that your church runs 19.8.1 or that the behavior holds on other versions. Check your own version (`GET /api/Utility/GetRockSemanticVersionNumber`; the anonymous GET normally works) and re-test on your sandbox before relying on an entry for a risky change. Untagged entries below are older observations from Rock 17–19-era builds.

## General build notes (older observations)

- Use the MCP buildlib and guarded write APIs for pages, blocks, HtmlContent, workflows, metrics, badges, attributes and reports. Clone a shared report when the change should affect only one page; ReportField sorting uses ColumnOrder.
- New metrics need partitions. Resolve SQL/manual source values and entity IDs locally. Do not backfill the current period that a scheduled calculation owns.
- Workflow action and launch endpoints have exhibited hangs; inspect for an already-created record before retrying. Prefer launch_workflow's WorkflowEntry path. New action configuration may need a WorkflowType cache refresh. Criteria-skipped actions can still signal success; design completion/branching explicitly.
- Full HtmlContent versions avoid WYSIWYG stripping; ApprovedDateTime affects which version renders. Use UTC, exact bytes, hashes, and edit_block_content for surgical edits. New blocks can require page cache refresh. Resave REST-created routes in the browser if registration is stale.
- Auth order matters: specific allows before deny-all, verify actual effective access. Use role membership rather than scattered individual permissions.
- ASP.NET wraps content in a form: use type="button" for non-submit buttons. Test overlays against Rock navigation and validate mobile layout. Never conclude from API success that UI is correct.
- For file bytes use a verified binary path; the source installation required hex through Lava because base64 was corrupted. Cookies and API tokens are different authentication mechanisms.
- Native e-sign, Person Entry matching, AttributeMatrix, dashboard caching, and Lava behavior are covered in the retained recipe references. Inspect configuration names/guids to resolve current IDs.

## Observed on Rock 19.8.1 (one installation, 2026-11-08)

- **`/-` after an unclosed `{` deletes the rest of the template, with a normal HTTP 200.** Rock reads `/-` as the start of its `/- ... -/` block comment and removes everything up to the next `-/`, or to the end of the template, across lines. `A{ 1/-1 }Z` renders `A{ 1`; CSS such as `.x{grid-row: 1/-1;}` truncates everything after it; a SQL string containing `/-` inside `{% sql %}` breaks the same way. Without a preceding `{` it is harmless (`a/-b`, `d.replace(/-/g,'')`). Fix: write `1 / -1` with spaces, or wrap the static code in `{% raw %}`. Search existing blocks for `/-` before an upgrade or a big edit. `measured, verified on 19.8.1, 2026-11-08`
- **Lava comparisons and conversions.** A SQL integer column compared with `==` to a Lava string is equal in both directions (older notes elsewhere said it never matched; that is wrong on 19.8.1). An empty string is truthy and nil is falsy. `AsInteger('12abc')` is nil, `AsInteger('1.9')` is 1, `AsInteger('-4')` is -4. Keep `| AsInteger` as an input guard anyway. `measured, verified on 19.8.1, 2026-11-08`
- **A raw SQL insert into a security role is invisible until a cache clear.** After a raw `GroupMember` INSERT into a security-role group, Rock still reported the person as not in the role (`IsInSecurityRole` false) until a Cache Manager clear. The row had no created/modified-by values and no History rows. `measured, verified on 19.8.1, 2026-11-08`
- **`{% modifygroupmember %}` takes effect at once and leaves an audit trail.** `{% modifygroupmember id:'0' ... securityenabled:'false' %}` in a block whose EnabledLavaCommands include `RockEntityModify` made the role effective immediately with no cache clear, stamped created/modified-by with the viewing person, filled `GroupTypeId` itself and wrote History rows. `/api/Lava/RenderTemplate` refuses it ("The Lava command 'RockEntityModify' is not configured for this template"), so it needs an admin-locked block or a Lava Application endpoint with that command enabled. `measured, verified on 19.8.1, 2026-11-08`
- **v1 REST refuses to add security-role members** ("Security role membership cannot be managed through this endpoint", 403) but allowed the DELETE. Add role members through Rock's own save logic (the UI, or the entity command above); if a tool falls back to SQL, clear the cache afterward. `measured, verified on 19.8.1, 2026-11-08`
- **A plugin can register a REST controller that some keys cannot call even with Auth rows.** One installed plugin refused both a staff session and an administrator REST key (403) because it had its own server-registration check. Separately, a plugin's REST controller arrived with no Auth rows of its own and inherited the entity-wide RestController default. Review each new plugin's controllers after installing it. `measured, verified on 19.8.1, 2026-11-08`
- **19.8.1 already logs the saves that "Enable Server Model Validation" will block.** The exceptions are `Rock.Security.AttributeValueValidationException` and `PropertyValidationException` in the ExceptionLog. The setting is under Admin Tools > Settings > Security > Security Settings and needs a Rock restart. Any value containing `{{`, `{%` or `{[` counts as Lava, even JSON. Text attributes have Allow Lava / Allow HTML options; Memo always allows Lava and has an Allow HTML option; HTML, Code Editor, Lava and Structured Content field types are unrestricted. One installation had logged about 130 such exceptions in a month, from workflow attributes holding JSON fingerprints, email bodies and sign-up text. Fix those attributes before anyone turns the setting on, and put Lava/HTML/JSON only in attribute types that allow it. Source: community.rockrms.com/connect/safely-turn-on-field-validation `measured; verified on 19.8.1, 2026-11-08`
- **Rock keeps every AI agent chat forever, including full tool results.** The rows sit in `AIAgentSession` / `AIAgentSessionHistory` with no cleanup setting yet. A Rock core developer said in the Rock community chat (2026-10-23) that deleting them is safe and a cleanup tool is coming. On one installation a staff-facing agent had several hundred sessions and thousands of messages, and a finance agent's sessions held giving results. Treat both tables as sensitive data. `measured; verified on 19.8.1, 2026-11-08`

## Rock 19.8 REST and Lava changes (traced)

- **19.8 tightened REST security; expect 401/403 on writes that worked on 19.4.** Changing blocks, attributes, REST security, persisted datasets, workflow triggers, person aliases or entity types over REST needs **Administrate**. REST changes to workflow action types are admin-only by default. Launching a workflow over REST checks the workflow type's permissions. Changing a metric's SQL or Lava source needs Administrate on the metric. Binary file endpoints apply file security. The built-in Presence REST login and the v1 AI Provider endpoints were removed. Source: Rock 19.8 release notes. `traced; applies to 19.8`
- **19.8 Lava/text changes.** Communication recipient addresses no longer render Lava (except a System Communication's To). The Entity Property Set, Entity Attribute Set and Redirect to Page workflow actions treat attribute values as plain text. The AI Send Communication tool is limited to one recipient. Source: Rock 19.8 release notes. `traced; applies to 19.8`
- **v1 REST rejects related records nested in a POST or named in a PATCH** ("save them separately"; Rock issue #7144, hotfixed in 19.8.1). Allow-listed collections: TransactionDetails, PhoneNumbers, ScheduledTransactionDetails. Send the parent, then each child as its own call. Since 19.5 (issue #7083) a v1 REST insert also needs Edit on the new entity. `traced; applies to 19.8`
- **The WorkflowActionType full-entity POST/PUT hang is a confirmed Rock bug (issue #6954), fixed only in v20.0.** PATCH works. The SQL-insert workaround in `skills/rock-build/SKILL.md` therefore still applies to 19.x. `traced; applies to 19.8`

## Removals coming in v20 and v21 (traced)

Plan replacements before these upgrades. Count your own blocks with SQL on `Block` joined to `BlockType` before you plan. Source: community.rockrms.com/connect/product-grooming-roadmap. `traced`

- v20 (expected second half of 2026) removes the legacy WebForms **Workflow Entry** block. New builds use the Obsidian Workflow Entry block.
- v21 (expected first half of 2027) removes **Dynamic Data**, **Page Parameter Filter**, **Activate Workflow**, core **FontAwesome** support, and the Lava **`{% execute %}`** tag.
- `{% execute %}` also breaks as Rock moves to .NET Core. Spark's advice (Rock community chat, 2026-10-28) is to replace it with a small C# plugin built with the rock-dev-tool CLI. Don't add new `execute` uses.
- v20 adds native agent skills that write through Rock's service layer (Auth, Defined Values, Categories and global attributes; workflow types, actions and forms; adding or updating blocks and pages, which copies page Auth to the block, checks the zone and flushes the page cache; Lava Applications; a community knowledge base). Tool results include GUIDs. After a v20 upgrade these should replace the riskiest raw SQL inserts (WorkflowActionType, Auth, Block). `traced, v20`

## From Rock core docs and source (traced)

From Spark's documentation and the Claude Code setup in Spark's own Rock repository (github.com/SparkDevNetwork/Rock, `.claude` folder on the develop branch).

- **Lava `sql` writes bypass Rock's cache, so flush it yourself.** The Lava `cache` command supports `tags:` (clear a tag from Cache Manager) and caps each item at 200 KB by default. `traced`
- **Lava Application endpoints (`/api/v2/lava-app/...`) grant no View by default.** The `javascript` and `stylesheet` commands don't work inside endpoints, and a GET must not change data. v20 fixes failures for non-admins when the Lava Application Developers role is inactive, and intermittent 404s after a save. `traced`
- **Check the model before writing raw SQL.** Model tables have `CreatedDateTime`, `ModifiedDateTime`, `CreatedByPersonAliasId` and `ModifiedByPersonAliasId` (PersonAlias ids, not Person ids); lighter entity tables do not. `IsSystem` exists only on some entities, and assuming it is the most common failure. Look up `EntityTypeId` by Name and other rows by Guid; never hard-code ids. Order new rows from `MAX + 1`, not 0. Use `IF NOT EXISTS` guards and finish with a verify SELECT. `sqlcmd` needs `QUOTED_IDENTIFIER ON` or deletes on tables with filtered indexes fail. A business record made by SQL needs `Person.GivingId = 'P<id>'`; a new Person needs a PersonAlias and a family group. Spark's templates use `GETDATE()`; this kit's time-zone rule applies instead (see `skills/rock-build/SKILL.md`). `traced`
- **Auth rules: first match wins, so order matters.** A per-person rule needs a low or negative `Order`, or a stock role's Allow wins first; put Deny All Users last. Guard record-level Auth inserts with `NOT EXISTS` on any row for that record and action. An Auth row with `EntityId = 0` changes the default for the whole entity type. Group-type role grants (CanView/CanEdit/CanManageMembers) override Auth Deny rules on groups. View and Tag are allowed by default; Edit and Administrate are denied. Core has no protection against locking yourself out. `traced`
- **The `PersonTokenCreate` and `PersonById` Lava filters have no security check, and admins pass every check.** Never expose those filters to user-controlled input on a public page, and prove access with a limited staff user, never an admin. `traced`
- **A workflow action's Active and Order attributes do nothing.** The action component overrides them; the real position is `WorkflowActionType.Order`. Writing the attribute silently creates a junk AttributeValue, which explains why `Active=False` on an action is ignored. `CriteriaAttributeGuid` is a Guid column, and a wrong value silently never matches. `traced`

## Rock AI agents and MCP clients

- **Agent instructions cap at about 1,800 characters**, and Claude follows them unevenly over MCP. MCP clients do not receive the organization context or agent instructions automatically. Keep in-Rock instructions basic and put detailed how-to in a skill on the user's side, with a note to read it before changing Rock. (Rock core developer, Rock community chat #ai, and Spark docs) `summarized`
- **Claude and Codex can cache an MCP server's tool list for up to about a day.** Refresh the connector after changing tools in Rock. The tool-count ceiling depends on total size (one builder lost tools above about 260); prefer a few broad tools. (Rock community chat #ai) `summarized`
- **Organization context** (Admin Tools > Settings > AI Agents > Settings) is added to every chat agent request: keep it short and factual (terminology, Group Type ids), with no behavior rules; simple Lava works. (Spark AI agent docs) `traced`
- The in-Rock chat agent runs on Rock IQ (Spark Connected Services, prepaid). Chats that showed "Unknown error" after 15–25 messages show the real error as of 19.8. (Rock 19.8 and Rock community chat) `summarized`
- Older fixes: agents had no current date until 19.4 (issue #6984); an MCP OAuth issuer trailing-slash mismatch breaks some clients (issue #6974). `traced`
- Tool-authoring conventions are in `skills/rock-build/SKILL.md`, "Agent tool conventions".

## From other Rock builders (summarized, unverified on 19.8.1 by this kit)

Other churches' and vendors' published findings, restated in this kit's own words. Tier and version are theirs. Sources: Consta-Tech AIskill-RockRMS, Dwell rock-plugins, Triumph rock-claude-plugins, ONE&ALL rock-agent-kb, Good News Church recipes and Favor rock-mcp, all public repositories.

- **`{% modifyentity %}` runs Rock's save hooks; raw `{% sql %}` writes skip them.** It fires PreSave/PostSave, fills `ModifiedDateTime`/`ModifiedByPersonAliasId` and writes History; raw SQL also skips attribute Default Values on insert. Rules: one action per block; `[[ attribute key:'...' ]]` keys are not Lava-rendered, so use literals; an empty `[[ property ]]` writes NULL; setting `Guid` fails; the result is keyed by entity type name, so use a named `return:`. (Consta-Tech, measured on v18.2.4; Good News Church) `summarized`
- **`{% dbtransaction %}` wraps modifyentity/deleteentity.** A `{% sql %}` write inside it can't report failure, rendered output inside is discarded on rollback, and `forcerollback:'true'` is a dry run. `enablecontextisolation` needs v19.3+. (Consta-Tech, from source) `summarized`
- **Once a Lava entity command runs, later UPDATEs in the same render save nothing (inserts still work).** Seen when launching a workflow inside an entity-command block (Rock issue #7155, open as of 2026-11-08). A failed modify also poisons later saves in the same render, and an entity command's `where:` is Dynamic LINQ, so a blank value breaks it. Split such work across renders and guard inputs. (ONE&ALL) `summarized`
- **A `{% sql %}` timeout throws away the whole rendered template and still returns HTTP 200**, showing "Lava Error: (Block: sql) Execution Timeout Expired". The default is 30 s; set `timeout:` on heavy queries. (Consta-Tech, v18.2.4) `summarized`
- **`Default` replaces only null or empty.** In `.lava.sql` files, `//-` Lava comments are stripped but `--` SQL comments reach SQL Server. (Consta-Tech) `summarized`
- **An HTML Content block with Cache Duration > 0 caches per block and context parameter, not per person.** It can serve one person's output to another; never set it on a block that renders per-person data (use `{% cache %}` with the person in the key). Validate Markup rejects a `</div>` that appears in only one `if` branch, and Require Approval hides saves until approved. (Consta-Tech, v18.2.4) `summarized`
- **`{% workflowactivate %}` with its parameters spread over several lines throws a blank-key error.** The zero-indent workaround drops reserved parameters, so keep the tag on one line. (Consta-Tech) `summarized`
- **Workflow ordering.** Add a Persist Workflow action before a SQL action that reads the previous form's attributes. A WorkflowLauncher failure can come after side effects that already succeeded, so check the action log before retrying. (ONE&ALL) `summarized`
- **Test Lava Application endpoints as a non-admin, because admins bypass endpoint security.** Send the `X-Helix-CSRF-Protection: true` header from the page. (Good News Church) `summarized`
- **Persisted datasets can carry a page's config and data, built at refresh time, so the page makes no database calls on load.** (Dwell) `summarized`
- **SQL shortcuts** (attribute-value views, checksum filters, alias resolution, date keys, indexed filters) are collected in `skills/rock-query/SKILL.md`. (Triumph, Dwell, Consta-Tech, ONE&ALL) `summarized`
- **v1 OData quirks.** `$skip` needs a preceding `$orderby` or Rock returns 500. Don't compare enums to integers in `$filter`. Rock's firewall may 403 a default `Python-urllib` User-Agent. Over v2 REST prefer PATCH to PUT, because PUT can blank fields you left out. (Favor; ONE&ALL) `summarized`
- **`AISkillTool.ToolType`: 0 = ExecuteCode, 1 = ExecuteLava, 2 = AIPrompt.** `/GetAvatar.ashx?PhotoId=<id>&Text=<initials>` avoids a database lookup per image. (Triumph) `summarized`
